# 两台电脑联机：真人或自定义 AI

每台电脑运行一个原生 SC2 窗口，各自选择控制方式。支持真人对真人、真人对 AI（任一方）、AI 对 AI。AI 是本项目 `agent.py` 的策略；不是战网大厅的内置电脑。原有单机人机入口仍可使用。

## 准备

1. 两台 Windows 电脑各安装 StarCraft II，并使用相同引擎版本。复制同一份本项目代码和地图；不用复制 `.deps`、`.cache`、`.retro`、`sc2/runs`。
2. 另一台电脑安装 `uv` 后，在项目根目录运行 `./sc2/setup/windows.ps1`。依赖使用现有锁定版本，没有新增包。
3. 游戏不在默认目录时，先设置 `$env:SC2PATH='你的 StarCraft II 安装目录'`。
4. 两台电脑要能通过 IPv4 互通：同一局域网，或已连接的虚拟局域网/VPN。异地优先用虚拟局域网。本工具不提供 NAT 穿透或中继。

## 开一局

房主在项目根目录运行：

```powershell
.\sc2\start-windows.ps1 host --control human
```

按 Enter 后，终端显示本局随机口令。把**房主的局域网/VPN IPv4 地址和口令**告诉对方。`0.0.0.0` 只是监听所有网卡，不是对方要填写的地址。

另一方运行（替换示例地址）：

```powershell
.\sc2\start-windows.ps1 join --address 192.168.1.20 --control human
```

按 Enter 并输入口令。双方校验并加载完成后**自动开始**，直接切到各自的 SC2 窗口操作；不需要进入战网大厅。窗口标题会显示真人/AI 和实际玩家编号。

任一方想让自定义 AI 操作，把自己的 `--control human` 改成 `--control ai`。例如：

```powershell
# 房主的 AI 对战远端真人/AI
.\sc2\start-windows.ps1 host --control ai
# 加入方选择 AI
.\sc2\start-windows.ps1 join --address 192.168.1.20 --control ai
```

AI 模式仍显示原生窗口供本方视角观战；请勿手动下令干预 AI。控制方式在启动时确定，中途不切换。真人槽位不会运行策略或注入 API 指令。双方都使用正常视野、相同地图属性及缩圈规则。

## 网络与退出

默认房间协调端口为 **TCP 14380**，SC2 对局预留 **14381–14384（TCP/UDP）**。双方防火墙应允许与对方的局域网/VPN 地址通信；若自定义 `--port P`，双方必须相同，对局端口相应为 `P+1` 到 `P+4`。脚本不会自动修改防火墙或路由器。SC2 控制 API 仅监听本机 `127.0.0.1`，不需要对外开放。

首次启动如果 Windows 提示网络访问，请允许用于本次联机的网络。若只停在“等待另一位玩家”，检查房主地址、口令和 TCP 房间端口；若双方已连接但卡在加载，检查游戏版本和四个对局端口。程序有超时，失败后重新开房，不会无限等待。

口令用于入房身份校验；对局流量没有由本工具额外加密。仅与可信朋友连接，异地使用已有 VPN。双方游戏版本、地图、规则必须完全一致，不一致会停止；策略文件可以不同，分别记录哈希。

对局结束自动保存并退出。提前结束请在启动终端按 **Ctrl+C**，对方也会收到结束通知；断线、超时、中止不会计作正常胜负。本版不支持断线重连。

## 记录与验证

每台电脑独立保存 `sc2/runs/<时间>-lan-host或join/`，内含录像、manifest、事件和本方视野的观测。两份记录共享 `room_id`，保存双方控制方式、实际玩家编号、引擎/地图/规则/策略哈希。只有双方都收到且确认一致的引擎终局结果，才标记 `status=complete`；统计战绩时必须检查该状态和控制方式。`--hidden` 明确标记为 `source=real_engine_diagnostic`，不作为真人成绩。

回放使用已有入口，并保留同目录 manifest：

```powershell
.\sc2\start-windows.ps1 watch --replay 'sc2/runs/<本局目录>/game.SC2Replay'
```

离线协议及控制路由检查：

```powershell
& .deps/sc2-win/Scripts/python.exe -m unittest sc2.test_lan -q
```

`--hidden --yes` 仅用于自动诊断，不用于真人操作。真人槽位的隐藏诊断只能证明没有注入 AI 命令，不能证明真人操作手感。当前联机入口的可视操作面向 Windows；本机 Linux 4.10 与 Windows 5.0.17 版本不同，不能混连。


本机验收（2026-11-07）：58 项离线检查通过。以下使用同一 Windows 电脑的两个独立 Python/SC2 进程，通过本机局域网 IPv4 连接，窗口隐藏：

| 房主 / 加入方 | 结果 |
|---|---|
| AI / AI | 正常终局，双方胜负一致，两份有效录像 |
| 真人 / AI | 无人操作的真人槽位，正常终局，两份有效录像 |
| AI / 真人 | 换边正常终局，两份有效录像 |
| 真人 / 真人 | 进入同一局；加入方在诊断上限停止，房主收到中止，双方无胜负记录 |

上述全部零动作错误，真人槽位发送的 API 指令为零。记录见 `runs/lan-smoke-004`、`runs/lan-smoke-005`、`runs/lan-matrix-001/summary.json`，最终汇总为 `runs/lan-validation.json`；前期失败诊断仍保留，没有改写成成功结果。相同名称造成槽位冲突、同时保存录像造成空录像的问题已修复，并加入回归检查。

尚未验证两台物理电脑或真实异地网络，也没有将隐藏真人槽位诊断当作真人操作验收。跨机连接仍取决于双方网络互通和防火墙配置。


## 本机卡顿排查

Windows 启动器统一限制玩家窗口最高 120 FPS、隐藏客户端和菜单最高 30 FPS。只限制渲染，AI 决策频率和缩圈规则不变；普通人机、联机、原生录像入口共用同一配置。

2026-11-07 的同机双可见窗口诊断中，GPU 占用采样为 91%/94%；两窗限制 60 FPS 后采样为 18%/9%，用户反馈改善但仍不流畅，操作时整局速度约 16 loops/s。单个可见真人窗口（120 FPS）加隐藏 AI（30 FPS）一局正常完成，双侧分别约 22.59/22.71 loops/s，观测间隔最长 0.235/0.250 秒，零动作错误。这些是引擎推进和负载证据，不等于测得屏幕始终保持 120 FPS；最后一轮的主观手感未确认。同机双真人可见窗口的问题仍未确认完全解决。完整记录见 `runs/windows-performance-validation.json`。

同机人机使用 `./sc2/start-windows.ps1`，它自动隐藏 AI 窗口。真正的两台电脑联机时，房主电脑只运行 `host`，另一台运行 `join`，每台各有一个窗口。测试时不要把同一台电脑上同时运行两个可见真人端的表现当作跨机网络验收。
