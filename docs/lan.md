# 两台电脑联机：真人或自定义 AI

每台电脑运行一个原生 SC2 客户端，默认独占全屏，各自选择控制方式；加 `--windowed` 可恢复 1600×900 窗口。支持真人对真人、真人对 AI（任一方）、AI 对 AI。AI 可选原有 `default`、决赛冠军 `a`、决赛 `b` 、护弓版 `a2`、远程残局版 `a3` 或撤退救援版 `a4`，通过 `--control ai --ai a` 指定；不是战网大厅的内置电脑。未指定时启动器会显示菜单，直接 Enter 使用原有 AI；自动化可明确传 `--ai` 或使用 `--yes` 保持默认。真人端不替远端选择 AI。原有单机人机入口仍可使用。

## 连续多局

```powershell
# 房主决定局数和自己的控制方式
.\start.cmd host --control human --rounds 5
# 另一台电脑加入；控制方式也可以改为 ai
.\start.cmd join --address 192.168.1.20 --control ai
```

`--rounds` 只接受 host 设置，范围 1～1000，默认 1。每局地图内先显示约 5 秒准备倒计时（Faster 下 112 loops）；可以选兵，但六个兵全部暂停移动与攻击，缩圈和比赛时限尚未开始。结束后保留结果画面至少 5 秒，再自动加载下一局；两端 SC2 进程一直复用，不必关闭或重新连接；等待自动换局即可，无需点击退出。

AI 可见窗口在每局开始时使用距离 100 的居中镜头，真人仍为 30，俯仰和朝向不变。镜头不锁定，AI 仍只取得本方正常视野。缩圈后的当前边界及外圈变红；未来内圈保持绿色，当前边界更粗。

多局记录放在同一个输出目录的 `round-001`、`round-002` 等子目录，每局各有 `game.SC2Replay`、`manifest.json`、观测和决策日志；`series.json` 记录整组状态。单局保持原来的录像路径。断线、录像保存失败或看门狗超时会停止整组，已完成局的录像保留。双方需使用新版脚本和地图（房间协议 2）。

## 准备

1. 两台 Windows 电脑各安装 StarCraft II，并使用相同引擎版本。复制同一份本项目代码和地图；不用复制 `.deps`、`.cache`、`.retro`、`sc2/runs` 和 `.env`。
2. 使用根目录 `start.cmd` 启动。脚本自动准备 uv、Python 3.10 和锁定依赖，第一次安装需要联网。
3. 没有配置 `SC2PATH` 时，脚本会询问 SC2 安装目录并验证 `SC2Data` 和 `Versions/Base*/SC2_x64.exe`，保存到本机根目录 `.env`。以后自动读取，环境变量优先。支持带空格和中文的路径；路径失效时会重新询问。
4. 两台电脑要能通过 IPv4 互通：同一局域网，或已连接的虚拟局域网/VPN。异地优先用虚拟局域网。本工具不提供 NAT 穿透或中继。

## 开一局

房主在项目根目录运行：

```powershell
.\start.cmd host --control human
```

默认是**空密码**，加入时不会询问口令。把**房主的局域网/VPN IPv4 地址**告诉对方。`0.0.0.0` 只是监听所有网卡，不是对方要填写的地址。

另一方运行（替换示例地址）：

```powershell
.\start.cmd join --address 192.168.1.20 --control human
```

按 Enter 确认准备好。双方校验并加载完成后**自动开始**，直接切到各自的 SC2 窗口操作；不需要进入战网大厅。窗口标题会显示真人/AI 和实际玩家编号。

需要限制入房时，在双方命令后添加相同的 `--key my-room-key`（8～128 字符）；不加则保持空密码。

任一方想让自定义 AI 操作，把自己的 `--control human` 改成 `--control ai`。例如：

```powershell
# 房主的 AI 对战远端真人/AI
.\start.cmd host --control ai
# 加入方选择 AI
.\start.cmd join --address 192.168.1.20 --control ai
```

AI 模式默认显示原生全屏画面供本方视角观战；请勿手动下令干预 AI。AI 端可加 `--no-window`，例如 `.\start.cmd host --control ai --no-window`，加入方同样支持。它隐藏游戏窗口，AI 仍正常出招并保存录像；这类 AI 对局保持正常对局标记，不会自动算作诊断。真人控制不能使用 `--no-window`，它也不能与 `--windowed` 同用。Windows 仍运行图形客户端，加载时可能短暂显示窗口；Linux AI 使用无渲染客户端。控制方式在启动时确定，中途不切换。真人槽位不会运行策略或注入 API 指令。双方都使用正常视野、相同地图属性及缩圈规则。

## 网络与退出

默认房间协调端口为 **TCP 14380**，SC2 对局预留 **14381–14384（TCP/UDP）**。双方防火墙应允许与对方的局域网/VPN 地址通信；若自定义 `--port P`，双方必须相同，对局端口相应为 `P+1` 到 `P+4`。脚本不会自动修改防火墙或路由器。SC2 控制 API 仅监听本机 `127.0.0.1`，不需要对外开放。

首次启动如果 Windows 提示网络访问，请允许用于本次联机的网络。若只停在“等待另一位玩家”，检查房主地址、口令和 TCP 房间端口；若双方已连接但卡在加载，检查游戏版本和四个对局端口。程序有超时，失败后重新开房，不会无限等待。

空密码房间允许能连到房间端口的客户端加入；设置非空 `--key` 后才有口令验证。对局流量没有由本工具额外加密。仅与可信朋友连接，异地使用已有 VPN。双方游戏版本、地图、规则必须完全一致，不一致会停止；策略文件可以不同，分别记录哈希。

对局结束自动保存并退出。提前结束请在启动终端按 **Ctrl+C**，对方也会收到结束通知；断线、超时、中止不会计作正常胜负。本版不支持断线重连。

## 记录与验证

每台电脑独立保存 `sc2/runs/<时间>-lan-host或join/`，内含录像、manifest、事件和本方视野的观测。两份记录共享 `room_id`，保存双方控制方式、实际玩家编号、引擎/地图/规则/策略哈希，并记录本方所选 AI 的 `policy_name`。只有双方都收到且确认一致的引擎终局结果，才标记 `status=complete`；统计战绩时必须检查该状态和控制方式。`--hidden` 明确标记为 `source=real_engine_diagnostic`，不作为真人成绩。

回放使用已有入口，并保留同目录 manifest：

```powershell
.\start.cmd watch --replay 'sc2/runs/<本局目录>/game.SC2Replay'
```

离线协议及控制路由检查：

```powershell
& .deps/sc2-win/Scripts/python.exe -m unittest tests.test_lan -q
```

`--hidden --yes` 仅用于自动诊断，不用于真人操作。真人槽位的隐藏诊断只能证明没有注入 AI 命令，不能证明真人操作手感。当前联机入口的可视操作面向 Windows；本机 Linux 4.10 与 Windows 5.0.17 版本不同，不能混连。

## 本机卡顿排查

Windows 启动器统一限制玩家窗口最高 120 FPS、隐藏客户端和菜单最高 30 FPS。只限制渲染，AI 决策频率和缩圈规则不变；普通人机、联机、原生录像入口共用同一配置。

2026-11-07 的同机双可见窗口诊断中，GPU 占用采样为 91%/94%；两窗限制 60 FPS 后采样为 18%/9%，用户反馈改善但仍不流畅，操作时整局速度约 16 loops/s。单个可见真人窗口（120 FPS）加隐藏 AI（30 FPS）一局正常完成，双侧分别约 22.59/22.71 loops/s，观测间隔最长 0.235/0.250 秒，零动作错误。这些是引擎推进和负载证据，不等于测得屏幕始终保持 120 FPS；最后一轮的主观手感未确认。同机双真人可见窗口的问题仍未确认完全解决。完整记录见 `runs/windows-performance-validation.json`。

同机人机使用 `./scripts/start-windows.ps1`，它自动隐藏 AI 窗口。真正的两台电脑联机时，房主电脑只运行 `host`，另一台运行 `join`，每台各有一个窗口。测试时不要把同一台电脑上同时运行两个可见真人端的表现当作跨机网络验收。


本次连局验收（2026-11-07）：68 项相关离线检查通过。最终地图使用 Windows 5.0.17 做隐藏 AI/AI 连续两局，双方各复用同一个 SC2 进程，四份录像有效、胜负一致、零动作错误；准备期间单位位置和生命不变且 AI 无指令，终局后实际保留 5.83～5.99 秒。原生窗口目视确认距离 100 的 AI 镜头能完整显示五圈，当前边界与外圈为红色。记录见 `runs/series-smoke-003/validation.json`。此前 `series-smoke-002` 在引擎启动、尚未读地图时发生 API ping 超时，已保留失败记录；重试成功。尚未验证两台物理电脑的多局连战。
