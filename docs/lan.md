# 两台电脑联机：真人或自定义 AI

## 图形联机大厅

两台电脑都双击根目录 `lobby.vbs`，也可运行 `start.cmd lobby`。双击时不弹出终端；首次启动在后台准备环境，缺少游戏路径时显示目录选择框。启动日志位于 `sc2/runs/lobby-setup.log`、`sc2/runs/lobby-setup-error.log` 和 `sc2/runs/lobby-ui.log`。

1. 房主点击“创建房间”，窗口显示本机 IPv4 候选地址；选择双方可互通的局域网 / VPN 地址告诉对方。
2. 加入方输入房主 IPv4，保持相同端口，点击“加入房间”。
3. 各自在“本方”下拉框中选真人、原版 AI、A、B、A2、A3、A4、A5 或 A6；双方能看到对方的选择和准备状态。
4. 房主选择对局速度（慢速优先选择标注“流畅”的约 0.43×、0.57×、0.71×、0.86×；保留 1× 及原来的精确倍速）及连续局数（1～1000，默认 1），加入方只能查看并自动跟随。双方各自勾选“开启本方游戏声音”（默认开启，含音乐，切到后台仍可播放）。AI 可勾选本方“不显示游戏画面”，真人不支持隐藏。
5. 各自点击“准备”。准备后本方设置锁定，两边都准备后自动启动游戏，不需要房主再点击开始。

大厅按房主设置连续开局，默认打开可见的 SC2 游戏画面；勾选隐藏的 AI 在后台运行。AI 由本方所选策略控制，显示时可观战，勿手动干预。默认全屏，`start.cmd lobby --windowed` 使用窗口模式。点击“退出房间”可以中断等待或对局；窗口在清理完成后可重新建房或加入。修改已准备的选择需要退出后重新连接。对局结束会显示录像目录。

双方应使用图形大厅连接；它不能与直接启动的旧 `host` / `join` 命令混用。大厅复用原有引擎、地图及规则校验、结果确认和录像保存；下述命令行入口继续可用。双方需使用支持局数和声音选项的新版大厅（大厅协议 3、对局配置协议 4）。大厅协议不提供断线重连或网络穿透，网络与端口要求见下文。

1× 和四个“流畅”慢速档使用原生实时模式，由房主在准备倒计时内通知地图设置引擎速度并锁定。其余精确倍速使用同步步进，由房主控制推进节奏。倍速作用于双方行动、倒计时和缩圈，AI 仍每 4 个游戏帧决策。实际速度受机器性能和网络往返延迟限制，高延迟下可能达不到所选速度。隐藏模式仍运行 SC2 客户端，并非无图形开销；加载时可能短暂出现游戏窗口。

“流畅”慢速档使用原生实时模式，由房主在准备倒计时内通知地图设置引擎速度并锁定。其余精确倍速使用同步步进，由房主控制推进节奏。倍速作用于双方行动、倒计时和缩圈，AI 仍每 4 个游戏帧决策。实际速度受机器性能和网络往返延迟限制，高延迟下可能达不到所选速度。隐藏模式仍运行 SC2 客户端，并非无图形开销；加载时可能短暂出现游戏窗口。

“流畅”慢速档使用引擎原生 Slower / Slow / Normal / Fast，分别为 9.6、12.8、16、19.2 游戏步/秒；相对于 Faster 的精确比例是 3/7、4/7、5/7、6/7，界面的两位小数是近似值。游戏、缩圈、倒计时和 AI 决策仍按同一游戏时钟推进，绘制由原生实时模式连续运行。`--speed 0.43/0.57/0.71/0.86` 选择这些档位。双方必须更新代码和地图。

原来的 0.25×、0.5×、0.75×、1.5×、2× 继续通过同步步进实现；低速时状态更新稀疏，可能不流畅。可见窗口渲染上限仍为 120 FPS。官方网络协议没有独立的任意实时倍速字段，但本地图通过 Galaxy 的 `GameSetSpeedValue` 设置原生档位，不需要逆向引擎。

## 连续多局

```powershell
# 房主决定局数和自己的控制方式
.\start.cmd host --control human --rounds 5
# 另一台电脑加入；控制方式也可以改为 ai
.\start.cmd join --address 192.168.1.20 --control ai
```

Windows 命令行可添加 `--sound` 开启本方音效、音乐和后台声音，`--no-sound` 关闭；命令行默认静音，大厅默认有声。声音只影响本机，不由房主统一控制，也不覆盖系统音量或游戏内各音量滑块。

`--rounds` 只接受 host 设置，范围 1～1000，默认 1。每局地图内先显示约 5 秒准备倒计时（Faster 下 112 loops）；可以选兵，但六个兵全部暂停移动与攻击，缩圈和比赛时限尚未开始。结束后保留结果画面至少 5 秒，再自动加载下一局；两端 SC2 进程一直复用，不必关闭或重新连接；等待自动换局即可，无需点击退出。

AI 可见窗口在每局开始时使用距离 100 的居中镜头，真人仍为 30，俯仰和朝向不变。镜头不锁定，AI 仍只取得本方正常视野。缩圈后的当前边界及外圈变红；未来内圈保持绿色，当前边界更粗。

多局记录放在同一个输出目录的 `round-001`、`round-002` 等子目录，每局各有 `game.SC2Replay`、`manifest.json`、观测和决策日志；`series.json` 记录整组状态。单局保持原来的录像路径。断线、录像保存失败或看门狗超时会停止整组，已完成局的录像保留。双方需使用新版脚本和地图（对局配置协议 4）。

## 准备

1. 两台 Windows 电脑各安装 StarCraft II，并使用相同引擎版本。复制同一份本项目代码和地图；不用复制 `.deps`、`.cache`、`.retro`、`sc2/runs` 和 `.env`。
2. 使用根目录 `start.cmd` 启动。脚本自动准备 uv、Python 3.10 和锁定依赖，第一次安装需要联网。
3. 没有配置 `SC2PATH` 时，脚本会询问 SC2 安装目录并验证 `SC2Data` 和 `Versions/Base*/SC2_x64.exe`，保存到本机根目录 `.env`。以后自动读取，环境变量优先。支持带空格和中文的路径；路径失效时会重新询问。
4. 两台电脑要能通过 IPv4 互通：同一局域网，或已连接的虚拟局域网/VPN。异地优先用虚拟局域网。本工具不提供 NAT 穿透或中继。

## 开一局

房主在项目根目录运行：

```powershell
.\start.cmd host --control human
```

默认是**空密码**，加入时不会询问口令。把**房主的局域网/VPN IPv4 地址**告诉对方。`0.0.0.0` 只是监听所有网卡，不是对方要填写的地址。

另一方运行（替换示例地址）：

```powershell
.\start.cmd join --address 192.168.1.20 --control human
```

按 Enter 确认准备好。双方校验并加载完成后**自动开始**，直接切到各自的 SC2 窗口操作；不需要进入战网大厅。窗口标题会显示真人/AI 和实际玩家编号。

需要限制入房时，在双方命令后添加相同的 `--key my-room-key`（8～128 字符）；不加则保持空密码。

任一方想让自定义 AI 操作，把自己的 `--control human` 改成 `--control ai`。例如：

```powershell
# 房主的 AI 对战远端真人/AI
.\start.cmd host --control ai
# 加入方选择 AI
.\start.cmd join --address 192.168.1.20 --control ai
```

AI 模式默认显示本方原生全屏画面。选中本方单位即可手动接管：AI 在下一次决策时停止给选中单位下发新指令，其他单位继续由 AI 控制；取消选择后恢复 AI 控制，多选或全选同样适用。已经发出的指令不会自动取消，可用手动命令覆盖。此功能适用于大厅或联机命令行的所有内置 AI，不会读取对手客户端的选区；单机 `human` 模式仍由真人控制全部本方单位。AI 端可加 `--no-window`，例如 `.\start.cmd host --control ai --no-window`，加入方同样支持。它隐藏游戏窗口，AI 仍正常出招并保存录像；这类 AI 对局保持正常对局标记，不会自动算作诊断。真人控制不能使用 `--no-window`，它也不能与 `--windowed` 同用。Windows 仍运行图形客户端，加载时可能短暂显示窗口；Linux AI 使用无渲染客户端。真人/AI 模式在启动时确定；AI 模式中可通过选区临时接管单位。真人槽位不会运行策略或注入 API 指令。双方都使用正常视野、相同地图属性及缩圈规则。

## 网络与退出

默认房间协调端口为 **TCP 14380**，SC2 对局预留 **14381–14384（TCP/UDP）**。双方防火墙应允许与对方的局域网/VPN 地址通信；若自定义 `--port P`，双方必须相同，对局端口相应为 `P+1` 到 `P+4`。脚本不会自动修改防火墙或路由器。SC2 控制 API 仅监听本机 `127.0.0.1`，不需要对外开放。

跨机器时，大厅通过 Python 转发 SC2 原生 TCP/UDP 游戏端口，SC2 本身仍按本机连接方式握手；只接受已连接对端的游戏流量。退出或连接失败会关闭转发和监听端口。两端需同时更新代码（对局配置协议 4），同机连接仍直接运行。

首次启动如果 Windows 提示网络访问，请允许用于本次联机的网络。图形大厅需允许 `pythonw.exe`，命令行需允许 `python.exe`，不能只放行 `SC2_x64.exe`。若只停在“等待另一位玩家”，检查房主地址、口令和 TCP 房间端口；若双方已连接但卡在加载，检查游戏版本和四个对局端口。程序有超时，失败后重新开房，不会无限等待。

空密码房间允许能连到房间端口的客户端加入；设置非空 `--key` 后才有口令验证。对局流量没有由本工具额外加密。仅与可信朋友连接，异地使用已有 VPN。双方游戏版本、地图、规则必须完全一致，不一致会停止；策略文件可以不同，分别记录哈希。

对局结束自动保存并退出。提前结束请在启动终端按 **Ctrl+C**，对方也会收到结束通知；断线、超时、中止不会计作正常胜负。本版不支持断线重连。

## 记录与验证

每台电脑独立保存 `sc2/runs/<时间>-lan-host或join/`，内含录像、manifest、事件和本方视野的观测。两份记录共享 `room_id`，保存双方控制方式、实际玩家编号、引擎/地图/规则/策略哈希，并记录本方所选 AI 的 `policy_name`。只有双方都收到且确认一致的引擎终局结果，才标记 `status=complete`；统计战绩时必须检查该状态和控制方式。`--hidden` 明确标记为 `source=real_engine_diagnostic`，不作为真人成绩。

回放使用已有入口，并保留同目录 manifest：

```powershell
.\start.cmd watch --replay 'sc2/runs/<本局目录>/game.SC2Replay'
```

离线协议及控制路由检查：

```powershell
& .deps/sc2-win/Scripts/python.exe -m unittest tests.test_lan tests.test_lan_transport tests.test_lan_ui -q
```

`--hidden --yes` 仅用于自动诊断，不用于真人操作。真人槽位的隐藏诊断只能证明没有注入 AI 命令，不能证明真人操作手感。当前联机入口的可视操作面向 Windows；本机 Linux 4.10 与 Windows 5.0.17 版本不同，不能混连。

## 本机卡顿排查

Windows 启动器统一限制玩家窗口最高 120 FPS、隐藏客户端和菜单最高 30 FPS。只限制渲染，AI 决策频率和缩圈规则不变；普通人机、联机、原生录像入口共用同一配置。

2026-11-07 的同机双可见窗口诊断中，GPU 占用采样为 91%/94%；两窗限制 60 FPS 后采样为 18%/9%，用户反馈改善但仍不流畅，操作时整局速度约 16 loops/s。单个可见真人窗口（120 FPS）加隐藏 AI（30 FPS）一局正常完成，双侧分别约 22.59/22.71 loops/s，观测间隔最长 0.235/0.250 秒，零动作错误。这些是引擎推进和负载证据，不等于测得屏幕始终保持 120 FPS；最后一轮的主观手感未确认。同机双真人可见窗口的问题仍未确认完全解决。完整记录见 `runs/windows-performance-validation.json`。
